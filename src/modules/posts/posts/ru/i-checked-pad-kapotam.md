В <a href="/posts/ru/i-checked/">прошлой заметке</a> я рассказывал, зачем сделал себе чек-листы и как они выглядят. Здесь — про то, как это устроено внутри: четыре решения, которые мне самому нравятся, и почему они такие.

Коротко про стек: Vue 3, TypeScript, Ionic и Vite, сверху Capacitor для сборок под iOS и Android. Сервера нет вообще.

## Офлайн без Workbox

Приложение должно открываться без сети: список проверяют у двери, а не за столом. Обычно для этого берут Workbox. Я посмотрел, что мне от него нужно, и получилось три вещи: положить файлы сборки в кэш, отдавать их оттуда и удалять старый кэш после обновления.

Это около ста строк, так что я написал свой плагин для Vite. Он цепляется к `generateBundle`, собирает имена всех файлов сборки и генерирует `sw.js`:

```ts
const precacheFiles = [...PUBLIC_ASSETS, ...bundleFiles];
const cacheVersion = createHash("sha256")
  .update(JSON.stringify(precacheFiles))
  .digest("hex")
  .slice(0, 12);
```

Главное здесь — версия кэша. Vite и так добавляет хэш содержимого в имена файлов. Изменился код — изменился список имён — изменился хэш списка — получился новый кэш. Отдельно вести версию не нужно, и забыть её поднять невозможно.

Сам воркер делает три вещи:

- навигацию берёт из сети и только при ошибке отдаёт сохранённый `index.html` — так онлайн сразу приходит свежая версия;
- остальные файлы сначала ищет в кэше: имена у них с хэшем, устареть они не могут;
- при активации удаляет кэши прошлых версий.

Чего тут нет: фоновой синхронизации, набора стратегий, маршрутов. Мне они не нужны — данных с сервера приложение не получает.

Цена простоты тоже есть. Воркер кладёт в кэш всю сборку сразу, при первом же заходе, — выборочной загрузки нет. А новая версия не подменяет открытую страницу сама: приложение показывает «Новая версия готова», и обновиться нужно кнопкой.

## Бэкап, который сначала проверяют

Данные лежат на устройстве, в Capacitor Preferences, обычным JSON. Синхронизации нет, поэтому единственная страховка — выгрузить всё в файл и потом из него восстановиться.

Восстановление заменяет все списки и историю. Значит, файл нужно проверить целиком до того, как что-то трогать. Проверка возвращает не «да» или «нет», а один из трёх ответов:

```ts
export type BackupParseResult =
  | { status: "valid"; backup: AppBackup }
  | { status: "unsupported-version"; version: number }
  | { status: "invalid" };
```

Средний вариант нужен ради человека. «Файл повреждён» и «файл сделан в более новой версии приложения» — разные сообщения и разные действия: во втором случае достаточно обновиться.

Внутри — скучная ручная проверка каждого поля: у списка есть название и хотя бы один пункт, время напоминания похоже на время, дни недели — от 1 до 7. Плюс потолки: не больше 500 списков, 500 пунктов в списке и 100 записей истории. Библиотеку для схем не подключал: формат один, а лишняя зависимость уехала бы в бандл.

## Бюджет бандла

В CI есть скрипт на тридцать строк. Он складывает размеры файлов в `dist/assets` и роняет сборку, если JavaScript тяжелее 1,25 МБ или всё вместе тяжелее 1,75 МБ — считаются несжатые байты.

Смысл не в цифре, а в том, что рост становится заметным: подключил тяжёлую библиотеку — сборка красная.

## Деплой, который проверяет себя

Сайтов два: лендинг на `ichecked.app` и само приложение на `app.ichecked.app`. Оба выкладываются по SFTP из одного воркфлоу GitHub Actions.

У такого деплоя есть слабое место: «файлы скопированы» не значит «сайт обновился». Поэтому при сборке в оба сайта кладётся `version.json` с хэшем коммита, а после выкладки скрипт идёт на прод и сверяет:

```js
async function expectRevision(url) {
  const response = await fetchWithRetry(url);
  const metadata = await response.json();
  if (metadata.revision !== expectedRevision.toLowerCase()) {
    throw new Error(
      `${url} serves revision ${metadata.revision ?? "unknown"}, expected ${expectedRevision}.`,
    );
  }
}
```

Запросы повторяются до шести раз с растущей паузой. Тот же скрипт проверяет, что каждая страница лендинга отвечает и содержит свой текст, что файлы подтверждения для поисковиков на месте и что приложение закрыто от индексации.

Часть проверок появилась после конкретных граблей. Лендинг копировался в артефакт по списку разрешённых файлов, и английская страница `/install/` тихо в него не попала. Теперь копируется всё, кроме исходников, а воркфлоу сравнивает список сгенерированных страниц со списком в артефакте.

И ещё одна мелочь: старые файлы приложения удаляются с сервера не сразу, а через 14 дней — чтобы открытая у кого-то прошлая версия не осталась без своих файлов.

## Что изменилось за два месяца

Первая заметка вышла в сентябре, и с тех пор проект в ящик не вернулся:

- у готовых списков появились свои страницы на сайте — выход из дома, спортзал, поездка, закрытие рабочего места и другие; каждая печатается одним листом с пустыми клетками, если бумага удобнее телефона;
- списком можно поделиться ссылкой;
- на карточке списка видно время сегодняшней проверки — не нужно открывать историю, чтобы вспомнить, проверял ли;
- появились инструкция по установке на домашний экран, настройка размера текста и шаблон «ребёнок идёт один»;
- в русской, украинской и белорусской версиях приложение теперь обращается на «вы».

QR-код на двери из прошлой заметки так и остался идеей.
